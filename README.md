# Hebrew Verb Map

A "Paradigm Explorer" — a radial-wheel UI for exploring Biblical Hebrew verb
paradigms. Every form shown is pulled from **actual attested occurrences**
in the Hebrew Bible (Open Scriptures Hebrew Bible morphology + Westminster
Leningrad Codex text, cross-checked against Strong's lexicon) — nothing is
generated from memory or theoretical rules. If a form doesn't occur in
Scripture, it isn't shown; that's a feature, not a gap to "fix."

See [`docs/maintenance-guide.md`](docs/maintenance-guide.md) for the full
data model, root-key conventions, and the ten extraction-pipeline
requirements this project depends on getting right (compound morph-code
parsing, homonym safety, participle state, etc.).

## Repo layout

```
data/roots/*.json      — one file per root, keyed by Strong's number
                          (H1980.json, H3557.json, ...). SOURCE OF TRUTH.
pipeline/
  pipeline.py           — corpus extraction pipeline
  fetch_corpus.sh        — clones the source texts, pinned to fixed commits
scripts/
  build.py               — reads data/roots/, produces dist/
src/
  template.jsx            — UI code for the Claude.ai artifact version
  template.html           — UI code for the offline single-file version
tests/
  test_data.py            — schema validation + corpus cross-verification
dist/                     — BUILD OUTPUT, gitignored, never hand-edited
docs/
  maintenance-guide.md
.github/workflows/
  validate.yml            — CI: schema checks on every push/PR
  deploy.yml              — publishes dist/ to GitHub Pages after validate passes
```

`dist/` is never committed. It's generated by `scripts/build.py` and
republished automatically by CI. **Every edit happens in `data/roots/`.**

## Why per-root files instead of one big data file

The original version of this project kept everything in one large embedded
JS object. That made every edit touch the same multi-thousand-line blob,
which is how a whole batch of new roots went silently missing from the UI
for a while (the display-order array fell out of sync with the data and
nobody could see the diff). With one JSON file per root:

- a git diff for adding or fixing a root shows *exactly* that root, nothing else
- `ROOT_ORDER` (display order) is *computed* from the files present, not a
  second hand-maintained list that can drift
- CI can validate every file's schema and re-verify it against a fresh
  corpus extraction before it ever reaches `main`

## Setup

```bash
git clone <this-repo>
cd hebrew-verb-map
pip install pytest

# fetch the pinned source corpus (only needed for the corpus-verification
# tests and for extracting new roots -- not needed just to build dist/)
pipeline/fetch_corpus.sh

# run the fast tests (schema, duplicates, homonym safety)
pytest tests/test_data.py -q -k "not TestAgainstCorpus"

# run the full corpus cross-verification (slower, needs the corpus fetched)
pytest tests/test_data.py::TestAgainstCorpus -q

# build the distributable files
python3 scripts/build.py
# -> dist/hebrew-verb-map.jsx   (paste into a Claude.ai artifact)
# -> dist/hebrew-verb-map.html  (open directly, fully offline)
# -> dist/data.json             (just the four data structures)
```

## Adding a new root

Working with Claude (chat or Claude Code): give the root, the stem(s), and
your gloss(es) for each stem. Claude resolves the Strong's number
(checking for homonyms), extracts every attested form for the requested
stems from the pinned corpus, applies the ten pipeline rules from the
maintenance guide, and adds one new file to `data/roots/`.

Working by hand: copy the schema from an existing file in `data/roots/`,
name it `H<number>.json`, run `pytest tests/test_data.py` to check it, then
`python3 scripts/build.py` to confirm it builds.

Either way, run the tests before committing — see `.github/workflows/validate.yml`
for exactly what CI will check.

## Current status

303 of 1,437 Hebrew verb entries in Strong's (Aramaic entries are out of
scope — different stem-letter system). See `docs/maintenance-guide.md`
§3 for known edge cases (hollow/geminate roots substituting pilpel/poel
for piel, roots with no attested qal, etc.).
